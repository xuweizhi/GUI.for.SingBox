# 上游 v1.26.1 合并设计

## 背景

当前 `main` 基于 `gui-for-cores/main` 的旧共同祖先 `69139a8`，包含 69 个本地独有提交。上游 `gui-for-cores/main` 已更新到 `f5a8933`（标签 `v1.26.1`），包含 10 个本地尚未完整合入的提交。

三方合并预演发现 13 个内容冲突。冲突集中在前端依赖、模态框、应用壳层、定时任务、类型声明和首页概览。目标是在保留本地 WebUI、backend worker、当前节点控制、节点测速和 systemd 适配的前提下，完整合入上游 `v1.26.1`。

## 合并策略

使用非快进 merge 合入 `gui-for-cores/main`，保留上游提交拓扑，为后续同步建立清晰基线。不使用批量 `ours`、`theirs` 或重置后重放本地提交。

合并完成后创建一个独立的 merge commit。设计文档提交和代码 merge commit 分开，便于审查。

## 冲突处理

### 依赖与环境

- `frontend/.env` 使用上游版本号 `v1.26.1`，保留本地 `VITE_APP_RUNTIME = wails`。
- `frontend/package.json` 保留本地 WebUI 构建、测试和加密订阅依赖，同时采用上游依赖版本升级。
- `frontend/pnpm-lock.yaml` 不手工拼接。先完成 manifest 合并，再使用 pnpm 10.23.0 重生成。
- `go.mod` 和 `go.sum` 保留本地 `gorilla/websocket`、`robfig/cron/v3`，采用上游 Wails 2.13 和 `golang.org/x/*` 版本，最后运行 `go mod tidy`。

### 模态框与应用壳层

- `Modal/index.vue` 以本地已加固的生命周期状态机为骨架，保留幂等最小化、外部关闭回调和持久模态销毁行为。
- `interaction.ts` 保留本地 `destroy()` 兼容 API 和幂等清理，避免破坏 `ResourceSelect` 等调用方。
- About 使用上游命令式 modal 路径；`stores/app.ts` 与 `GlobalOverlays.vue` 必须成套调整，确保只存在一条渲染路径。
- `AppShell.vue` 和 `NavigationBar.vue` 吸收上游样式钩子，同时保留 WebUI 隐藏桌面标题栏和退出入口。
- `OverView.vue` 吸收上游样式钩子和 modal 调用方式，同时保留当前节点卡片、五卡响应式布局和 WebUI 内存统计回退。

### 定时任务

`stores/scheduledtasks.ts` 以本地 backend worker 与前端 Cron 协同架构为准。不得恢复上游“所有任务都创建前端 Cron”的逻辑，避免重复执行。上游“运行后返回日志”的目标已由本地 worker 和前端双路径覆盖，只吸收不改变调度归属的语义。

### 类型与配置生成

- `types/app.d.ts` 保留本地 `declare global`、模块导出、`IProfile` 和 WebUI、日志、加密订阅、定时任务扩展字段。
- 选择性吸收上游 direct inbound、`RulesetHub` 命名和注释调整，不用上游整文件覆盖。
- `utils/generator.ts` 合入 direct inbound 改动，同时保留本地 DNS IP 地址不生成 `domain_resolver` 的修复。

## 不可回退行为

- WebUI 登录、退出、双模式构建和浏览器运行时桥接保持可用。
- backend worker 管理的任务不会同时创建前端 Cron。
- 当前节点卡片和节点测速功能保持可用。
- WebUI 在 memory event 缺失时仍能显示 connections 内存统计。
- 模态框的关闭、最小化、恢复、销毁和外部关闭回调保持幂等。
- systemd 模板继续设置正确的 `HOME`、安全监听默认值和网络能力。

## 验证

依次执行以下验证：

1. 确认无未解决冲突和冲突标记。
2. 使用 pnpm 10.23.0 重生成并冻结验证 lockfile。
3. 运行前端类型检查和全量 Vitest。
4. 运行默认 Wails 前端和 WebUI 两套生产构建。
5. 运行 `go mod tidy`、`go mod verify` 和 `go test ./...`。
6. 运行 Wails Linux 构建。
7. 运行 systemd 单元契约测试和已安装单元静态校验。
8. 启动构建产物进行本地 headless HTTP 冒烟测试，不替换或重启当前生产服务。

任一验证失败时保留未提交的合并状态，定位并修复根因；全部通过后再创建 merge commit。

## 非目标

- 不在本次合并中重构本地 worker、WebUI 或节点测速架构。
- 不顺便修复与合并无关的既有测试夹具问题。
- 不推送远端。
- 不重启当前 systemd 服务。
